# Architecture

## Sync waves (`apps/`)

| Wave | Applications |
|---|---|
| -4 | argocd (self-managed) |
| -3 | cert-manager, sealed-secrets |
| -2 | trust-manager, cnpg-operator, keycloak-operator |
| -1 | cluster-config (ClusterIssuer, CA Bundle, CoreDNS rewrite, OIDC RBAC) |
| 0 | postgresql (CNPG `Cluster` keycloak-db) |
| 1 | keycloak (Keycloak CR, ingress, realm import) |
| 3 | headlamp |

Waves between Applications work because `argocd-cm` has a health check for
`argoproj.io/Application` (see `platform/argocd/values.yaml`).

## TLS and trust

- Root CA is generated on the host (`~/.k3s-gitops/ca`), never committed.
- cert-manager `ClusterIssuer/platform-ca` signs all ingress certificates.
- trust-manager publishes `ConfigMap/platform-ca-bundle` (system roots + CA) to all
  namespaces; argocd-server and Headlamp use it via `SSL_CERT_FILE`.
- The apiserver reads the CA from `/etc/rancher/k3s/platform-ca.crt`.

## DNS

`*.localtest.me` resolves to 127.0.0.1 (pinned in `/etc/hosts` by `01-host-prep.sh`).
On the host this hits Traefik (ports 80/443).
Inside pods a CoreDNS rewrite (`platform/cluster-config/coredns-custom.yaml`) sends
it to the Traefik service, so `https://keycloak.localtest.me/realms/platform` is
the same issuer URL for browser, pods and apiserver.

## SSO

| Client | Used by | Flow |
|---|---|---|
| `argocd` | Argo CD | OIDC code flow; `groups` claim → `argocd-rbac-cm` |
| `headlamp` | Headlamp, kube-apiserver | Headlamp sends the user's ID token to the apiserver; apiserver maps `oidc:<group>` → ClusterRoleBindings |

| Keycloak group | Argo CD | Kubernetes |
|---|---|---|
| platform-admins | role:admin | cluster-admin |
| viewers | role:readonly | view |

## Secrets

| Secret | Source |
|---|---|
| `cert-manager/platform-root-ca` | created by bootstrap script (never in Git) |
| `keycloak/keycloak-db-app` | generated by CloudNativePG |
| `keycloak/keycloak-initial-admin` | generated by Keycloak Operator |
| `keycloak/realm-secrets`, `argocd/argocd-oidc`, `headlamp/headlamp-oidc` | SealedSecrets from `04-seal-secrets.sh` |

CoreDNS forwards external names to `k3s/resolv.conf` (1.1.1.1, 8.8.8.8), not to
the host's systemd-resolved config.
